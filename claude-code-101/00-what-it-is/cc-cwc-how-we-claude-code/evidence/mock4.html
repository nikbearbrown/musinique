A Workshop · Enrolment Now Open

Learning to keep receipts:
an unhurried Saturday with Git.

In a single, small-room afternoon, twenty-four newcomers will build the mental model that most self-taught programmers assemble by accident over years — and leave with a repository, a workflow, and no more folders named final v2.

Written by the Editors · Illustrated by A. Kim · Printed in Boston

Every programmer, at some point, has stared at a folder titled project-final-FINAL-use-this-one and understood, dimly, that there must be a better way. There is. It is called version control, and for thirty-odd years the working craft of software has hinged on it.

Yet Git — the version-control system that runs the world's code — is famously charmless to learn. Its documentation is terse. Its metaphors leak. Its error messages have the tone of a bureaucrat who has already decided you're wrong. Most people first meet it through panic: an interview, a new job, a class where the professor said just push it to GitHub as if that were a complete sentence.

The premise

Our premise on Saturday is simple. In five hours, taught in a small room with real coffee and a real lunch, we can hand a newcomer the model that survives contact with actual work. Not a list of commands to memorise. A picture of what Git believes about your code — snapshots on a graph, branches as movable labels, remotes as other people's copies — and then enough hands-on practice for that picture to become second nature.

The rhythm

We alternate short lessons with longer stretches of practice. You will make your first commit before the morning is out, break something before lunch, and recover from it — with a command called reflog that will feel, briefly, like a small miracle. In the afternoon, we move to GitHub, open a pull request against a real repository, and review one another's work.

The last ninety minutes are yours. Bring the folder you've been meaning to put under version control. A mentor will sit with you. By 3 PM, that project has a home on the internet, a README you wrote, and a workflow you can keep using on Monday.

Who this is for

If you have opened a terminal at least once and can save a text file, you are ready. Prior programming experience is welcome but not required. If you already know Git and simply want the afternoon lab, tell us on the form — we'll seat you accordingly.
